# Audit finding resolutions and release gaps

Assessment of the `1852494e` baseline plus the uncommitted `chore/past-audit-cleanup` changes on 2026-11-21. **Fixed** means the described code path has a merged change or an explicitly identified fix on this branch and was checked against current source; it does not claim a live-chain exploit test. **Partial** means a material part remains. **Accepted/deferred** means the original risk remains by a deliberate scope or product decision. **Open** means no sufficient mitigation was found. PR and commit references are local Git evidence; the current source is the authority where a fix has evolved.

## CODEX (14 findings)

These IDs belong to the [November 16 CODEX report](CODEX_SECURITY_AUDIT_2026-11-16.md), not to V12. Several share a root cause with later V12 findings; the distinctions below matter to the remaining scope.

- **F-01 — Fixed.** #418 (`8b1f9bca`) changed both paymaster preparations to estimate with a non-executable simulation payload; the real proof, signature and authorization are assembled afterward. See [`tornado-cash` simulation](../../packages/tornado-cash/src/paymaster/simulation.ts) and the [Privacy Pools counterpart](../../packages/privacy-pools/src/paymaster/simulation.ts). This closes the original pre-consent executable-operation disclosure, assuming the simulation payload remains unusable on-chain.
- **F-02 — Guarded.** #409 (`6324afe9`) rejects random delegation with multiple notes or tail calls unless the caller explicitly sets `allowUnsafeRandomExecution`. The override is an intentional escape hatch; a caller using it owns the stranded-funds risk. See the [Tornado](../../packages/tornado-cash/src/state/thunks/paymasterWithdrawThunk.ts) and [Privacy Pools](../../packages/privacy-pools/src/state/thunks/paymasterWithdrawThunk.ts) guards.
- **F-03 — Acknowledged, unresolved.** The SDK recomputes the ASP root from received leaves, but the root does not bind leaf count. A malicious gateway can supply an upper tree level as leaves and hide real approvals while passing the root comparison. The [code says so](../../packages/privacy-pools/src/state/thunks/syncAspThunk.ts); the [configuration guide](../../docs/pages/privacy-pools/configuration.mdx) recommends a second source. The default IPFS path does not verify the CID multihash. This is a private-exit availability and possible public-ragequit privacy risk, not a proved theft path.
- **F-04 — Accepted unsupported pool-replacement lifecycle.** #413 (`50229726`) improved pool lifecycle/wind-down state, but [notes omit pool identity](../../packages/privacy-pools/src/state/selectors/notes.selector.ts) and [asset lookup returns the first historical pool](../../packages/privacy-pools/src/state/selectors/pools.selector.ts). Privacy Pools discovers pools dynamically; their addresses are not hardcoded. After an Entrypoint owner replaces one asset's pool, relayer preparation may fail safely on live-config mismatch while paymaster and ragequit can still route to the historical pool. Normal SDK exits for old or new notes are not guaranteed. The team does not foresee replacement and explicitly excludes it from this release's supported lifecycle; operators must upgrade routing and plan recovery for both pools before replacing one. Root verification does not fix routing. No code fix was made.
- **F-05 — Partial, source trust remains.** #414 (`27588450`) and #430 (`86438920`) compare pool leaves to the root at the synced block; this catches missing leaves. The root does not commit to all metadata: a Privacy Pools `PoolDeposited` can be omitted while its leaf remains, and `EntrypointDeposited`, `PoolRegistered`, `Withdrawn`, `Ragequit`, and Tornado `Withdrawn` events can be omitted or misreported. Ordinary sync may advance past them. A complete authoritative RPC rescan is the current recovery route. Tornado explicitly documents the withdrawal-event trust/privacy tradeoff in its [configuration guide](../../docs/pages/tornado-cash/configuration.mdx). Do not describe the whole external-source completeness issue as fixed.
- **F-06 — Fixed for the documented reorg window.** #413 (`50229726`) added Privacy Pools finalized cursors, pruning and replay; Tornado now has a finalized cursor, overlap scan and canonical replay in [syncEventsThunk](../../packages/tornado-cash/src/state/thunks/syncEventsThunk.ts). This depends on a truthful finalized RPC. Older corrupt saved state can still require a reset.
- **F-07 — Fixed on this branch.** [Withdrawal selection](../../packages/tornado-cash/src/state/selectors/withdrawals.selector.ts) now rejects an explicit zero or negative amount before either relayer or paymaster preparation selects notes. Omitted amount still means all notes. One regression test covers both the rejection and unchanged omitted-amount behavior; the patch changeset is `tornado-positive-withdrawal-amount.md`.
- **F-08 — Fixed for same-store preparations, with a recovery limit.** #443 (`2e7b9605`) reserves locally prepared signature nonces and makes the discovery gap configurable. A large gap created on another device or after losing the reservation can still go undiscovered unless the caller raises the gap; the cutoff itself is silent. See [discovery](../../packages/tornado-cash/src/state/thunks/discoverUserEventsThunk.ts).
- **F-09 — Fixed.** #431 (`02ce3e28`) rejects malformed legacy notes with a generic error and bounds input length; it no longer echoes the bearer note. See [parser](../../packages/tornado-cash/src/account/legacyNote.ts).
- **F-10 — Original executable leak fixed; error redaction partial.** #418 makes the operation sent for estimation non-executable, but Tornado [estimate.ts](../../packages/tornado-cash/src/paymaster/estimate.ts) still attaches the original error as `cause` and may expose simulation details in telemetry. Redact/summarize those fields if error objects can reach logs or analytics. Privacy Pools already uses a redacted error path.
- **F-11 — Acknowledged API behavior.** Tornado shield preparation may floor a request to representable denominations and return transactions for less than requested. The [options guide](../../docs/pages/tornado-cash/options.mdx) now says this. A caller must compare the returned transaction total with the intended amount before confirmation; the CLI enforces exactness. If 0.2.0 promises exact shield amount at the SDK boundary, change this behavior explicitly.
- **F-12 — Fixed.** #432 (`f44e524a`) added an exact subset search fallback to the greedy withdrawal selection in [withdrawals.selector.ts](../../packages/tornado-cash/src/state/selectors/withdrawals.selector.ts).
- **F-13 — Fixed.** #435 (`bac87f36`) preserves per-note input order and surfaces partial broadcast failures through an indexed aggregate error in the [Tornado broadcaster](../../packages/tornado-cash/src/plugin/broadcaster.ts).
- **F-14 — Acknowledged low-severity residual.** Privacy Pools shield preparations can derive one precommitment from the same discovered deposit index in [state-manager.ts](../../packages/privacy-pools/src/state/state-manager.ts), even sequentially before the first deposit is mined and synced. The upstream v1 contract is expected to reject a duplicate; that costs gas rather than principal if deployed bytecode matches. Wait for confirmation and sync between preparations, or manage the index explicitly, until it is reserved by the SDK.

## RedTeam: critical and high findings

The [RedTeam source](SOISPOKE_REDTEAM_AUDIT_2026-11.md) is dated November 21 but examines an older SDK/CLI baseline. The status below uses current Kohaku `1852494e`; statements about `kohaku-cli` are read-only checks of its separate `feat/v0.1.9` checkout, not changes in this branch. The report's **H2** is mentioned in its summary and recommended order but has no actual H2 finding section or supporting reproduction in the supplied Markdown.

- **C1 / TCC-1 — Original artifact-substitution exploit mitigated.** #345 (`ad9c520f`) pins the Tornado circuit and proving key URL to a commit and verifies SHA-256 for both before parsing/proving in [artifacts-integrity.ts](../../packages/tornado-cash/src/utils/artifacts-integrity.ts) and [prover-factory.ts](../../packages/tornado-cash/src/utils/prover-factory.ts). The current CLI uses packaged local artifacts instead of its old third-party mirror/cache. The prover still uses the legacy `new Function` witness format; the hardcoded digest is the security boundary. Verify the CLI's installed SDK artifact pin before its own release.
- **C2 / PPC-1 / PPF-1 — Fixed.** #346 (`e29a6193`) canonical-decodes relay data, checks the requested recipient and on-chain/quoted fee bounds before proving, and ranks by the decoded fee in [quoteThunk.ts](../../packages/privacy-pools/src/state/thunks/quoteThunk.ts). #445 (`6d6eccdb`) later strengthened expiry and signature-shape checks. The relayer cannot choose a different recipient through this path now.
- **H1 / TCF-1 — Fixed with a bounded-fee policy.** #347 (`70b93ba2`) caps Tornado relayer fees at a default 20% per note, checks an ERC-20 quote against the paymaster TWAP when available, and ranks actual fees in [quoteThunk.ts](../../packages/tornado-cash/src/state/thunks/quoteThunk.ts). Without a reference quote, the percentage cap is the remaining independent limit.
- **H2 — Accepted intentional fee policy; source report is incomplete.** #366 (`a98a88ff`) bounds bundler gas price against host RPC fee history and caps validation, pre-verification and post-op gas in each package's `paymaster/gas-bounds.ts`. Execution `callGasLimit` has no default ceiling unless the caller supplies `maxGasLimits`; there is no percentage-of-note fee cap. The maintainer chose this deliberately: a small note (for example 0.01 ETH) may reasonably spend most of its value on sponsorship. Privacy Pools still requires the fee to fit the sponsoring withdrawal, and Tornado requires it to be below the denomination. The prepared operation exposes its proof-bound fee for host/user review, and callers can set an absolute gas ceiling. A hostile or faulty bundler can still propose expensive execution within those affordability bounds if the host accepts it. This is an accepted tradeoff, **not** a complete code fix or a guarantee that the fee is economical. The supplied report mentions H2 in its summary and recommended order but omits its detailed finding section.
- **H3 / TCF-5 — Fixed in SDK and current CLI.** #347 (`70b93ba2`) introduced a static Tornado instance catalog and rejects unknown/mismatched registry pools in [syncPoolsThunk.ts](../../packages/tornado-cash/src/state/thunks/syncPoolsThunk.ts). The separate CLI now independently validates deposit target, selector/value and ERC-20 approval token/spender, and displays targets before confirmation (`kohaku-cli` commits `206da23`, `9168856`).
- **H4 / CLS-1 — Open in the separate CLI.** It still batches HD and stealth balance queries through the same RPC transport. This can link addresses at the provider. A separate privacy transport/session strategy is needed; unbatching on the same IP is insufficient.
- **H5 / PPF-3 — Fixed.** #391 (`a2177fd0`) replaced user-specific history block lookups with a public block grid and interpolated timestamps in [syncHistoryTimestampsThunk.ts](../../packages/privacy-pools/src/state/thunks/syncHistoryTimestampsThunk.ts). The old per-user block-query description no longer matches HEAD.
- **H6 / CLF-2 — Open in the separate CLI.** Railgun external unshield still derives an unreserved next public account with `peekNextAccounts`; a later `--next` can hand out that same address and link activity. Reserve a dedicated index or use a throwaway sender before its release.
- **H7 / PPC-2 / PPF-2 — Partial.** #349 (`68085b97`) rebuilt the ASP root from leaves and binds withdrawal proofs to a verified root. That defeats arbitrary changed leaf lists, but [syncAspThunk.ts](../../packages/privacy-pools/src/state/thunks/syncAspThunk.ts) explicitly acknowledges the upper-tree-level substitution allowed by a root with no leaf-count commitment; an attacker can still hide approvals and steer a user toward a public ragequit. The IPFS and 0xBow tree parsers also remain unbounded (V12 F-47). Keep this separate from the now-fixed self-reported-root bug.
- **H8 / PLG-1 — Fixed for first-party plugin secret managers, host isolation still open.** #353 (`3cf46090`) added [scopeKeystore](../../packages/plugins/src/host/scoped-keystore.ts); Privacy Pools and Tornado pass scoped wrappers to their secret managers/workers. A host that hands its raw keystore to arbitrary third-party plugins still grants arbitrary derivation, and explicitly allowed delegation paths can include an EOA path. Storage and network isolation remain host responsibilities. Do not claim an unrestricted third-party plugin sandbox.

## RedTeam: medium SDK, provider, supply-chain, and CI observations

- **PPF-5 (two sync heads) — Fixed.** `777a1b6a` pins Privacy Pools sync to one head in [syncThunk.ts](../../packages/privacy-pools/src/state/thunks/syncThunk.ts); #413 added a finalized rewind/replay window.
- **PPF-6 (Saga event metadata) — Partial.** #438 (`0022a866`) binds received pool deposit metadata to verified leaves, but root checks do not authenticate `Withdrawn`, `Ragequit`, Entrypoint metadata, or an omitted deposit event. The separate CLI's Saga client has no manifest public key. This overlaps CODEX F-05.
- **TCF-4 (Tornado sync finality, gaps, filtering and rollback) — Substantially fixed.** Current [syncEventsThunk.ts](../../packages/tornado-cash/src/state/thunks/syncEventsThunk.ts) verifies contiguous leaves/root, validates provenance, replays an unfinalized overlap and reports per-pool failures (#429/#430/#441). It still relies on honest authoritative RPC data and cannot promise that every network fault is recoverable.
- **TCF-3 (non-atomic multi-note paymaster withdrawal) — Accepted architectural residual.** The first note may be spent during validation while later notes execute afterward. #409 blocks an unsafe random sender unless explicitly overridden; a recoverable deterministic sender reduces principal-loss risk. Multi-note atomicity was not implemented and callers must handle partial execution and refunds.
- **PPF-7 (old PR #320 ASP cache) — Superseded.** That PR snapshot is not the current implementation. The [current cache](../../packages/privacy-pools/src/state/selectors/merkle-tree.cache.ts) compares leaf count and last leaf for append eligibility, then checks the expected root and rebuilds on mismatch; the separate leaf-count ambiguity in H7 remains.
- **PPC-3 (signature determinism) — Guarded within a session.** #351 added a default double-sign check on the first note envelope in each [SignatureSecretManager](../../packages/privacy-pools/src/account/signature-keys.ts) session; a caller can disable it only for a signer it knows to be deterministic. The check is memoized, so changing process-wide signing entropy later in the session is not detected for later envelopes. Freeze signer configuration or recheck if it can change.
- **PPC-5 (Ledger/compact signature framing) — Accepted format boundary; no algorithm change.** `canonicalRS` passes the supplied signature to viem `parseSignature`, which expects 65-byte `r‖s‖v`; it does not normalize raw Ledger-style `v‖r‖s` or 64-byte ERC-2098 compact signatures. The maintainer chose to keep the signature-derived note-secret algorithm and parser unchanged for this release. A host using such a signer must normalize its returned signature to supported `r‖s‖v` framing before passing it to `EnvelopeSigner`; otherwise note discovery can fail or derive different secrets. The [configuration guide](../../docs/pages/privacy-pools/configuration.mdx) conditions portability on canonical `r` and low-`s`. Source comments that claim signer framing is irrelevant and compact signatures work are inaccurate and remain a documentation caveat. Do not claim raw Ledger/compact signatures are supported by the SDK.
- **PPC-4 / PLG-11 (public EIP-712 note-signature phishing) — Accepted trust boundary.** An external dapp-facing signer can be asked to sign the public derivation typed data. The default scoped signer reduces exposure; hosts should use a dedicated signer/path and show the derivation request clearly.
- **PLG-2 (anon provider bootstrap) — Open trust assumption.** [anon/index.ts](../../packages/provider/src/anon/index.ts) reads the worker specifier and hash through the caller's bootstrap RPC. A hash learned from the same untrusted RPC does not independently authenticate the worker.

## Release judgment at this snapshot

The V12 crosswalk is **48 fixed/mitigated, 3 partial (F-1/F-24/F-31), 3 accepted residuals (F-38/F-42/F-50), 1 open outside the PPv1/TC scope (F-30), and 1 deliberately deferred with an open technical risk (F-47)**. This count describes the V12 issues only. It does not erase the distinct CODEX and RedTeam residuals above. `#410` documents F-38 rather than enforcing per-account host storage; the unmerged F-47 branch is not in this checkout.

The maintainer has made these decisions for this branch:

- **CODEX F-07 / RedTeam TCF-6: fix.** The shared Tornado selector now rejects explicit nonpositive amounts; omitted amount still selects all notes. The focused regression and typecheck passed. This is an SDK guard for an accidental full-balance withdrawal, not a change to denomination selection.
- **RedTeam PPC-5: accept the signer-format boundary.** Do not change the signature-derived note-secret algorithm or parser in this audit cycle. Raw Ledger `v‖r‖s` and ERC-2098 compact signatures are not SDK-supported inputs; an integration must normalize to `r‖s‖v` and verify restart recovery. The source comments overstate this support and remain a known documentation caveat.
- **RedTeam H2: accept the intentional paymaster cost policy.** A small sponsoring note may deliberately spend most of its value on gas. Keep the existing host-RPC gas-price/fixed-overhead bounds and optional `maxGasLimits.callGasLimit`; do not impose a default execution-gas or percentage fee ceiling. A costly bundler estimate within the note's affordability limit remains an accepted risk, and the host/user must review the exposed proof-bound fee before broadcast.
- **CODEX F-04: accept unsupported pool replacement.** The team does not anticipate replacing an asset's Privacy Pools v1 pool. If replacement is planned, SDK note-to-pool routing and a recovery plan for notes in both pools are required before the change. Dynamic discovery and root verification do not make current exits safe across replacement.
- **V12 F-42: accept conditional event-source trust.** Honest v1 pool logs are canonical, and a malformed or malicious Saga/RPC log is required for the alias. The root check cannot distinguish an aliased leaf even when the root RPC is honest, so a trusted source and full chain-RPC resync are the release assumption. No field guard was added; this remains an availability risk, not a proven theft path.

The branch's Tornado worker test failures came from the test assuming a browser concurrency level that Vitest did not supply. A test-only fixture now sets that level, and the full suite passes 482/482. Both scoped package builds and typechecks pass.
