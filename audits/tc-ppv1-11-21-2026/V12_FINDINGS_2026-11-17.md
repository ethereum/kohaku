# F-1: Concurrent Preparations Reuse One Nonce

- Link: https://v12.sh/kassandra/findings/1
- Severity: Low
- Status: Open
- Repository: ethereum/kohaku
  - Remote: https://github.com/ethereum/kohaku.git
  - Branch: master
  - Commit: 6324afe9c4cab9691b392b583d8b2ba366ab6130

## Report

The external preparation path reads the current EntryPoint nonce and native authorization nonce, then signs and returns a UserOperation using those snapshots. There is no reservation, per-sender lock, or re-read between `prepareExecutionAccount` and signing; each invocation constructs its own `verifiedExternalDelegator`, whose authorization cache is local to that invocation. Two concurrent preparations for the same external signer can therefore both sign different proof/fee/gas payloads with the same sender and EntryPoint nonce. EntryPoint nonce replay protection permits at most one of those operations, leaving the other rejected or displaced even though both passed the SDK's checks.

## Locations

- `packages/privacy-pools/src/account/execution-account.ts:74-110`: Current native and EntryPoint nonces are read without reservation.
- `packages/privacy-pools/src/account/external-delegator.ts:38-58`: Authorization cache is closure-local to one wrapper/preparation.
- `packages/privacy-pools/src/paymaster/utils.ts:211-223`: UserOperation builder accepts a caller-provided nonce with no coordination.
- `packages/privacy-pools/src/paymaster/utils.ts:263-307`: The same nonce is included in the signed UserOperation and serialized for broadcast.
- `packages/privacy-pools/src/state/state-manager.ts:524-573`: State-manager paymaster dispatch has no sender-scoped serialization around preparation.
- `packages/privacy-pools/src/state/thunks/paymasterWithdrawThunk.ts:171-189`: The thunk snapshots nonce state and creates a fresh signer wrapper per preparation.
</finding>

# F-2: Unverified empty scans advance the relayer registry cursor

- Link: https://v12.sh/kassandra/findings/2
- Severity: High
- Status: Open

  - Remote: https://github.com/ethereum/kohaku.git

  - Commit: 6324afe9c4cab9691b392b583d8b2ba366ab6130

## Report

Relayer synchronization advances its saved registry cursor whenever `RelayerRegistered` is empty, using the returned `toBlock` without validating that it represents safely observed chain coverage. In the chain-only path, `SyncService` obtains a `head` for its external-fetch decision but does not pass that bound into `DataService` for the subsequent registry query. `DataService` propagates the `toBlock` returned by `EthClient`, and `EthClient` derives that value from `provider.getBlockNumber()` when no explicit bound is supplied. Consequently, an empty log response paired with an inconsistent or future provider-reported block number is treated as complete coverage and persisted as the next starting cursor. A later sync then begins after the unobserved range rather than retrying it.

- `packages/tornado-cash/src/data/data.service.ts:99-131`: Event coverage is returned from the RPC result without an independent bound.
- `packages/tornado-cash/src/data/eth-client.ts:43-68`: Provider block number bounds the log query and is returned as coverage.
- `packages/tornado-cash/src/data/sync.service.ts:71-87`: Chain-only relayer synchronization propagates DataService toBlock.
- `packages/tornado-cash/src/state/thunks/syncRelayersThunk.ts:35-47`: Empty event results commit the unverified bound and return.

## Report

`PrivacyPoolsV1Protocol` creates a process-lifetime `delegationPaths` set and passes the same mutable collection to `scopeKeystore`. # F-4: Batch exact-output withdrawals omit direct-note execution gas

- Link: https://v12.sh/kassandra/findings/4
- Severity: Medium
- Status: Open
- Repository: ethereum/kohaku
  - Remote: https://github.com/ethereum/kohaku.git

## Report

Exact-output paymaster withdrawal preparation sets `grossAmount` to `requestedNet + estimate.fee` before constructing the operation. The estimate interface exposes tail-call inputs but no batch or extra-note-count input, and its paymaster branch prices `reasonableGasUnits` with `callGasLimit` limited to optional tail-call gas. During construction, a batch can select a sponsoring note plus `directNotes`, after which the thunk uses `reasonableGasUnitsForBatch` rather than the estimated baseline. That batch helper adds execution gas for each extra withdrawal, so the committed fee can exceed the amount included in `grossAmount`. The subsequent exact-output check detects the resulting net shortfall and rejects preparation rather than sizing the gross amount with the batch-aware fee.

# F-5: Reorgs permanently contaminate privacy-pools mirrored state

- Link: https://v12.sh/kassandra/findings/5
- Severity: High
- Status: Open
- Repository: ethereum/kohaku
  - Remote: https://github.com/ethereum/kohaku.git
  - Branch: master
  - Commit: 6324afe9c4cab9691b392b583d8b2ba366ab6130

## Report

The privacy-pools chain mirror treats synchronization as forward-only ingestion: it starts from a retained block cursor and merges newly fetched records into keyed maps. The log normalization sets `removed` to `false` and does not preserve a usable canonical block identity, while deposits, withdrawals, ragequits, pool leaves, pools, and assets have no removal or rollback path. Consequently, a reorganization of an already scanned range can retain records from the abandoned branch even when they are absent from the replacement range, and those records can also keep the effective scan point at a prior high-water mark. Retained withdrawals or ragequits can make notes appear spent in balance and history projections, while retained leaves can reconstruct a root that is not on-chain. Root verification rejects an unrecognized local root, but the failed synchronization does not prune the forked records or publish a repaired snapshot. The fix is to track canonicality and rewind/replay a reorg window, atomically replacing or pruning every affected event, leaf, registry, and cursor projection before publishing state.

## Locations

- `packages/privacy-pools/src/state/selectors/balance.selector.ts:50-54`: A matched ragequit forces the deposit balance to zero.
- `packages/privacy-pools/src/state/selectors/history.selector.ts:60-72`: The stale ragequit is included in history.
- `packages/privacy-pools/src/state/selectors/notes.selector.ts:184-201`: Unapproved recovery candidates require a positive balance.
