# Configuration

`createTCPlugin(host, params)` is the constructor. `protocolConfig` is the only field without a default.

```ts
import {
  createTCPlugin,
  TornadoCashConfigs,
  TornadoPaymasterConfigs,
} from '@kohaku-eth/tornado-cash'
```

`TornadoCashConfigs[1]` is mainnet. `TornadoCashConfigs[11155111]` is Sepolia. The object carries the instance registry (and the block it was deployed in), the relayer registry, the aggregator, the WETH address, and the ENS subdomain key the relayer list is read from.

## Options

| Field | Required | Role |
| --- | --- | --- |
| `protocolConfig` | yes | Deployment for this chain. Use `TornadoCashConfigs`. |
| `accountIndex` | yes | Keystore account. `0` is the first. |
| `paymasterConfig` | no | Per-chain ERC-4337 paymaster. Defaults to `TornadoPaymasterConfigs`. |
| `artifactsLoader` | no | Returns `{ circuitText, provingKey }`. The default downloads both. |
| `relayerConfig` | no | Fee window for relayer selection. Defaults to `{ minFee: 0.01, maxFee: 0.30 }`. |
| `secretManagerFactory` | no | Replaces the built-in pair of signature secrets and legacy BIP-32 secrets. |
| `minExternalSyncBlocksAmount` | no | How far behind a pool must be before `host.externalSyncProvider` is used. |
| `stateManagerWorkerUrl` | no | URL of the state worker, when the bundler cannot find the default one. |
| `initialState` | no | `() => Promise<Record<string, PublicRootState>>`. Seeds an empty store. |
| `relayerClientFactory` | no | Replaces the HTTP relayer client. It receives `host` indirectly through the factory you close over. |

```ts
const tornado = createTCPlugin(host, {
  accountIndex: 0,
  protocolConfig: TornadoCashConfigs[1],
  paymasterConfig: TornadoPaymasterConfigs,
  minExternalSyncBlocksAmount: 1_000,
})
```

The chain id comes from `host.provider`, not from `protocolConfig`. Point the provider at the same network as the config.

## Proving artifacts

The first unshield proves in-process. The default loader fetches:

- the circuit JSON, and
- the proving key binary

from the `tornado-cli` build published on GitHub. That is fine for a demo. A wallet ships or caches the files and returns them from `artifactsLoader`:

```ts
createTCPlugin(host, {
  accountIndex: 0,
  protocolConfig: TornadoCashConfigs[1],
  artifactsLoader: async () => ({
    circuitText: await readFile(circuitPath, 'utf8'),
    provingKey: await readFile(provingKeyPath),
  }),
})
```

`provingKey` is an `ArrayBuffer`. The CLI downloads once into the wallet's data directory and reads from disk after that, in [`src/utils/proving-artifacts.ts`](https://github.com/kassandraoftroy/kohaku-cli/blob/main/src/utils/proving-artifacts.ts).

## Relayer fee window

`relayerConfig` filters the on-chain relayer registry. A relayer is skipped when its `tornadoServiceFee` is below `minFee` or greater than or equal to `maxFee`, when its queue is longer than five, or when its `netId` disagrees with the provider's chain. ERC-20 withdrawals also skip relayers that do not publish ETH prices.

```ts
createTCPlugin(host, {
  accountIndex: 0,
  protocolConfig: TornadoCashConfigs[11155111],
  relayerConfig: { minFee: 0.01, maxFee: 0.1 },
})
```

The numbers are in the same unit as the relayer status field. The defaults accept fees from `0.01` up to, and not including, `0.30`.

`preferredRelayersEns` on a regular relayer unshield narrows this list further. The recommended [ERC-4337 paymaster path](/tornado-cash/options) does not use this registry filter.

## Secret manager

Leave `secretManagerFactory` unset. The worker then uses both managers:

- `SignatureSecretManager` for new deposits, at `m/29795'/1'/{accountIndex}'`.
- `SecretManager` so notes created with the older child-key scheme are still found.

A factory you pass replaces that pair. Return both if the wallet has historical notes, or only the scheme you intend to support on a fresh account.

```ts
import { SecretManager, SignatureSecretManager } from '@kohaku-eth/tornado-cash'

createTCPlugin(host, {
  accountIndex: 0,
  protocolConfig: TornadoCashConfigs[1],
  secretManagerFactory: async (params) => {
    const legacy = await SecretManager(params)
    const signature = await SignatureSecretManager(params)
    return { ...legacy, ...signature }
  },
})
```

`params.host` here is `{ keystore }`. `deriveAt` still has to answer the paths on the [host page](/host).

## Fast cold sync

`minExternalSyncBlocksAmount` does nothing until the host sets `externalSyncProvider`. When a pool is at least that many blocks behind the chain head, the plugin streams events from the external source and finishes the tail with `host.provider`.

```ts
createTCPlugin(host, {
  accountIndex: 0,
  protocolConfig: TornadoCashConfigs[1],
  minExternalSyncBlocksAmount: 1_000,
})
```

Omit the field to always scan with `eth_getLogs`. The CLI sets `1000` and attaches a saga-backed provider in [`src/utils/saga-external-sync.ts`](https://github.com/kassandraoftroy/kohaku-cli/blob/main/src/utils/saga-external-sync.ts). The host contract for that provider is on [The host](/host).

## Worker and initial state

State is built inside a worker so proving and tree updates stay off the UI thread. The package ships the worker script. Set `stateManagerWorkerUrl` when your bundler needs an explicit URL:

```ts
createTCPlugin(host, {
  accountIndex: 0,
  protocolConfig: TornadoCashConfigs[1],
  stateManagerWorkerUrl: new URL(
    '@kohaku-eth/tornado-cash/state-manager.worker.js',
    import.meta.url,
  ).href,
})
```

`initialState` returns a snapshot keyed the same way `dumpState()` writes it (`tornado-cash-state-…`). Use it to ship a checkpoint so the first open does not start at the registry's deployment block. The snapshot is a cache. The keystore still decides which notes belong to the user.

## Paymaster map

`TornadoPaymasterConfigs` is the default: a bundler URL, the EntryPoint v0.8 address, the paymaster, and a pool-to-adapter map for mainnet and Sepolia. Pass `paymasterConfig` with the same shape to use another bundler. Pool keys are lowercase addresses. A pool that is missing from the map can still be withdrawn through a relayer.

Use `mode: 'paymaster'` explicitly when preparing a withdrawal. The prepared operation carries the bundler URL and EntryPoint from the plugin's paymaster map; `createTCBroadcaster` uses those fields to submit it. See [deposits and withdrawals](/tornado-cash/options).
