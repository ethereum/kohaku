# Configuration

`createPPv1Plugin` is the short constructor. It accepts the fields a wallet always sets. `PrivacyPoolsV1Protocol` is the same plugin as a class, and it is where you pass a secret manager or a saga-backed data service.

```ts
import {
  createPPv1Plugin,
  PrivacyPoolsV1Protocol,
  PrivacyPoolsV1_0xBow,
} from '@kohaku-eth/privacy-pools'
```

Both return an object with `prepareShield`, `prepareUnshield`, `balance`, `notes`, `history`, `ragequit`, `estimateShield`, `estimateUnshield`, `sync`, and `registerDepositIndex`.

## Factory options

| Field | Required | Role |
| --- | --- | --- |
| `accountIndex` | yes | Keystore account. `0` is the first. Notes from a different index stay invisible. |
| `broadcasterUrl` | yes | Relayer URL, or a record of relayer id to URL. A string becomes `{ default: url }`. |
| `entrypoint` | yes | `{ address: bigint, deploymentBlock: bigint }`. Sync starts at `deploymentBlock`. |
| `aspServiceFactory` | no | Builds the association-set client. The default reads the set from IPFS. |
| `aspReviewServiceFactory` | no | Builds the review-status client. Off by default: deposits outside the set read as `'pending'`. See [Review status](#review-status). |
| `ipfsUrl` | no | Gateway used by the default IPFS client. Defaults to `https://ipfs.filebase.io/ipfs/`. |
| `paymasterConfig` | no | Per-chain ERC-4337 paymaster. Omit it to use the bundled mainnet and Sepolia map. |
| `initialState` | no | `() => Promise<Record<string, PublicRootState>>`. Seeds storage on an empty wallet. |
| `devOptions` | no | Redux safety checks. Both are off, because they are slow on a full pool state. |

`PrivacyPoolsV1_0xBow` is the entrypoint table:

| Chain id | Network |
| --- | --- |
| `1` | Ethereum mainnet |
| `11155111` | Sepolia |

```ts
const deployment = PrivacyPoolsV1_0xBow[1]

createPPv1Plugin(host, {
  accountIndex: 0,
  broadcasterUrl: {
    fast: 'https://fastrelay.xyz/relayer',
    backup: 'https://relays.example/privacy-pools',
  },
  entrypoint: {
    address: BigInt(deployment.entrypoint.entrypointAddress),
    deploymentBlock: deployment.entrypoint.deploymentBlock,
  },
})
```

These ids (`fast`, `backup`) are used only by the regular relayer mode. The recommended ERC-4337 paymaster path uses the bundler URL from `paymasterConfig`; `broadcasterUrl` remains a required constructor field. See [withdrawals](/privacy-pools/withdrawals) for preparation and broadcasting.

## Secret managers

The class defaults to `SignatureSecretManager`. It asks the host keystore for `m/28784'/1'/{accountIndex}'`, signs an EIP-712 `PrivacyPoolNote`, and hashes the signature into the nullifier and salt. The same key on a software signer and on a device that returns canonical `r` and low-`s` produces the same note.

```ts
import {
  PrivacyPoolsV1Protocol,
  SecretManager,
  SignatureSecretManager,
} from '@kohaku-eth/privacy-pools'

new PrivacyPoolsV1Protocol(host, {
  accountIndex: 0,
  entrypoint,
  relayersList: { default: 'https://fastrelay.xyz/relayer' },
  secretManager: (params) => SignatureSecretManager({
    ...params,
    signer: myEnvelopeSigner, // optional; default signs with the keystore
  }),
})
```

The `host` a secret manager receives has a scoped keystore: it derives below `m/28784'/1'` and the exact `delegation.path` of a paymaster unshield, and throws `KeystorePathNotAllowedError` for anything else.

`myEnvelopeSigner` implements `signEnvelope(envelope) => hex signature`. The domain and types are built by the SDK, so the device only signs that payload.

Note secrets are never stored. After a restart they are signed again, so the signer must return the same signature for the same envelope (RFC 6979). The first time a session needs a secret, the manager signs one envelope twice and throws `Note signer is not deterministic` if the two differ, before any deposit or change note uses it. That costs one extra signature per session, which is one extra prompt on a hardware wallet. Pass `verifyDeterminism: false` to `SignatureSecretManager` only for a signer you know is deterministic. With viem, leave `setSignEntropy` off.

`SecretManager` is the older BIP-32 scheme: child keys under `m/28784'/1'/{account}'/{secretType}'/{deposit}'/{secret}'`. It is a different note set. Passing it replaces the signature manager. Do that only for a wallet whose deposits were created with it.

[kohaku-cli](https://github.com/kassandraoftroy/kohaku-cli/blob/main/src/utils/plugins.ts) passes `secretManager: SecretManager` inside `createProtocolPlugin` because that wallet's existing deposits use the BIP-32 scheme. A new wallet can keep the default.

`relayersList` on the class is the same map the factory builds from `broadcasterUrl`.

## Explicit deposit indices

By default, `prepareShield` chooses the index above the highest recovered deposit. To choose the index yourself, pass `depositIndex`:

```ts
await pools.prepareShield(deposit, { depositIndex: 17 })
```

After a shield at an explicit index confirms, call `registerDepositIndex(17)`. By default, it first syncs public chain events (without refreshing the ASP tree), then attempts recovery. Pass `{ sync: false }` only when the events have already been synchronized. It returns `false` when those events lack a deposit for that index, and on a match it also recovers the deposit's withdrawals.

Discovery follows consecutive deposits from index zero and from each registered index, and it doesn't search the gaps between them. A wallet must keep each sparse index in its private recovery metadata and register it again after a restart. Registration lasts only for the session, and `dumpState` excludes credentials and their indices.

Preparing a transaction doesn't reserve its index, so two shields prepared before either confirms can choose the same index. Confirm and sync one shield before you prepare the next.

## Association set

The association set decides which deposits are approved. Until a deposit is in the set, its balance is `'pending'` and the relayer withdrawal path will not spend it.

The default client is `IPFSAspService`, which `fetch`es the tree from IPFS through `host.network`. Set `ipfsUrl` to point it at another gateway. A client that does not return the tree within 30 seconds is aborted through the `signal` passed to `getAspTree`, and the sync goes on with the last tree it accepted.

The client is not trusted. The plugin keeps only the leaves it returns, rebuilds the root from them, and rejects the set if that root is not the one in the Entrypoint's `RootUpdated` event. Each sync checks the rebuilt root against the Entrypoint's `latestRoot()`, and a withdrawal is only proved against a root checked that way in the same session. A root does not commit to the number of leaves, so a dishonest gateway can still make approved deposits look pending. Confirm a pending status with a second source, such as `OxBowAspService`, before you offer ragequit.

0xbow publishes the set over HTTP. Pass `OxBowAspService`:

```ts
import { OxBowAspService, createPPv1Plugin, PrivacyPoolsV1_0xBow } from '@kohaku-eth/privacy-pools'

const deployment = PrivacyPoolsV1_0xBow[1]

createPPv1Plugin(host, {
  accountIndex: 0,
  broadcasterUrl: 'https://fastrelay.xyz/relayer',
  entrypoint: {
    address: BigInt(deployment.entrypoint.entrypointAddress),
    deploymentBlock: deployment.entrypoint.deploymentBlock,
  },
  aspServiceFactory: () => new OxBowAspService({
    network: host.network,
    aspUrl: 'https://api.0xbow.io', // Sepolia: https://dw.0xbow.io
  }),
})
```

The CLI uses this client. Sepolia's URL is `https://dw.0xbow.io`.

A custom association set implements `getAspTree(state): Promise<bigint[][]>`. Only the first array, the leaves, is used.

### Review status

The set only tells approved deposits apart. A deposit the ASP declined, or one waiting on a proof of innocence, looks the same as one still under review. Pass `aspReviewServiceFactory` to tell them apart:

```ts
import { OxBowAspReviewService } from '@kohaku-eth/privacy-pools'

createPPv1Plugin(host, {
  // ...
  aspReviewServiceFactory: () => new OxBowAspReviewService({
    network: host.network,
    aspUrl: 'https://api.0xbow.io', // Sepolia: https://dw.0xbow.io
  }),
})
```

Each note then carries a `reviewStatus`, and each deposit in `history` an `aspStatus`:

| Status | Meaning |
| --- | --- |
| `'approved'` | In the association set. |
| `'pending'` | Not in the set, and not flagged. Still under review. |
| `'declined'` | The ASP declined it. This is final in almost every case, though the ASP can reverse a false positive. Offer ragequit. |
| `'poi_required'` | The ASP wants a proof of innocence before it approves the deposit. |

The option is off by default because it calls 0xbow's API. The client downloads every declined and proof-of-innocence-required deposit of the chain, never a lookup of one deposit, so 0xbow learns that the host uses Privacy Pools but not which deposits are its own. It calls once per sync of the chain state, whatever the accounts hold, since that state is shared by every account and the list is public.

The client is not trusted either. The set always wins: a deposit in it reads `'approved'` whatever the feed says, so the feed can mislabel an unapproved deposit but never make one spendable. If the feed fails, or does not answer within 10 seconds, the sync goes on with the last statuses it fetched. An account without `aspReviewServiceFactory` reads no statuses, not even ones fetched by another account sharing its `chainStorage`, so every deposit outside the set reads `'pending'` for it. Each fetch replaces the previous list, so a decline the ASP reverses goes back to `'pending'`.

A custom client implements `getFlaggedDeposits({ chainId }): Promise<{ precommitment, pool, status }[]>`, where `status` is `'declined'` or `'poi_required'`. Rows for pools of another entrypoint are ignored.

## Paymaster

Omit `paymasterConfig` and the plugin uses its bundled map: bundler URL, entrypoint, paymaster, and a pool-to-adapter table for mainnet and Sepolia. Override a chain when you run your own bundler.

```ts
createPPv1Plugin(host, {
  accountIndex: 0,
  broadcasterUrl: 'https://fastrelay.xyz/relayer',
  entrypoint,
  paymasterConfig: {
    1: {
      bundlerUrl: 'https://bundler.example/rpc',
      entryPointAddress: '0x4337084D9E255Ff0702461CF8895CE9E3b5Ff108',
      paymasterAddress: '0xPaymaster',
      poolsAccountsMap: {
        // pool address, lowercase -> adapter address
        '0xf241d57c6debae225c0f2e6ea1529373c9a9c9fb': '0xAdapter',
      },
    },
  },
})
```

`poolsAccountsMap` keys are lowercase pool addresses. A pool missing from the map cannot be withdrawn in paymaster mode. Relayer withdrawals ignore this table. The withdrawal options are on the [withdrawals page](/privacy-pools/withdrawals).

## Sync from saga

A cold `eth_getLogs` scan of mainnet is slow. `createSagaDataService` reads history from a saga CDN and asks the provider only for the blocks past the CDN's head.

```ts
import {
  createSagaDataService,
  PrivacyPoolsV1Protocol,
} from '@kohaku-eth/privacy-pools'

const dataService = await createSagaDataService({
  provider: host.provider,
  chainId: 1,
  sourceUrl: 'https://saga-pp-state.global.ssl.fastly.net/v2',
})

const pools = new PrivacyPoolsV1Protocol(host, {
  accountIndex: 0,
  entrypoint,
  relayersList: { default: broadcasterUrl },
  dataService,
})
```

The `/v2` index also carries each event's transaction hash, so synced events have their real `transactionHash`. The root index omits it and those events get `0n`.

Pool leaves are checked against the on-chain root, so a bad leaf stream fails the sync. Entrypoint events from the CDN have no such root. The RPC tail after the CDN's head still comes from `host.provider`.

Sepolia is not in that mainnet index. Leave `dataService` unset there and let the plugin scan with `eth_getLogs`. `initialState` can still drop a snapshot into storage so the first scan starts near the tip:

```ts
createPPv1Plugin(host, {
  accountIndex: 0,
  broadcasterUrl,
  entrypoint,
  initialState: async () => savedSnapshot,
})
```

The CLI seeds a bundled Sepolia snapshot and, on mainnet, builds its own saga `DataService` in [`src/utils/privacy-pools-saga.ts`](https://github.com/kassandraoftroy/kohaku-cli/blob/main/src/utils/privacy-pools-saga.ts).

`headBlock` on `createSagaDataService` clamps the CDN to a pinned chain, which is what you want against a fork. Omit it on a live network.

## Development checks

```ts
createPPv1Plugin(host, {
  accountIndex: 0,
  broadcasterUrl,
  entrypoint,
  devOptions: {
    enableImmutableCheck: true,
    enableSerializableCheck: true,
  },
})
```

Turn these on while you are debugging state. Leave them off in a wallet. They walk the whole pool on every update.

## Merkle tree builds

Large trees use workers when available. In Chrome MV3 service workers, React Native, or when workers fail to start or load, the default builder falls back to the calling thread. That preserves sync and proof generation, but the initial build can block that thread.

To control where the work runs, pass `merkleTreeBuilder` to `createPPv1Plugin` or `PrivacyPoolsV1Protocol`:

```ts
const pools = createPPv1Plugin(host, {
  accountIndex: 0,
  entrypoint,
  broadcasterUrl,
  merkleTreeBuilder: (leaves) => offscreen.createTree(leaves),
})
```

Here `offscreen.createTree` is your bridge. It returns a local proxy implementing the exported `MerkleTree` interface: a `root: bigint` property, plus `indexOf(leaf)`, `generateProof(index)`, and `insert(leaf)` methods. Methods can return promises. After `insert` resolves, the proxy's `root` must reflect the updated remote tree. Keep the remote tree alive while its proxy is in use; the SDK caches it and extends it incrementally. The bridge handles transport serialization (including bigint values); the SDK does not create the offscreen document or messaging channel.

The hook is used for ASP leaf validation, sync root checks, and withdrawal inclusion proofs. The SDK still checks roots against the chain. A custom builder's errors propagate so the wallet can reconnect its bridge and retry; only the default worker builder falls back automatically. Cache entries are separated by callback identity, so reuse a stable callback when reusing the same host.
