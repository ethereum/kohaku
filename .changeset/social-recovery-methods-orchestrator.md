Add the methods orchestrator. `MethodsOrchestrator` implements `IMethodsOrchestrator`. Its constructor takes the method registry, the action codec registry and the list of device bindings this runtime meets; the list is required and `none` is always met. Each of the three arguments is checked in full at construction, before any member can be called. The orchestrator holds no provider: it builds every approver context (the `ctx` argument the method implementations receive) from the request alone. `signingInput` and `enrollInput` throw `KitRefusalError` when no registered implementation serves the request's method, or when the implementation's device binding is not in the list. `replyFrom` and `configFrom` do not throw in those cases: they answer the typed failures `method-unsupported`, `request-unsupported` or `device-unavailable`, and pass an implementation's own failure on as a fresh frozen record. `verify` throws a `TypeError` when the proof is not hex bytes, a `RangeError` when the place is not the request's own and a `KitRefusalError` when no implementation serves the method; the `IMethodsOrchestrator.verify` comment now says so. `describeRequest` hands an implementation's `describe` a checked, frozen copy of the request instead of the caller's object. New constants: `METHODS_ORCHESTRATOR_UNBOUND`, `METHODS_ORCHESTRATOR_METHOD_UNSUPPORTED`, `METHODS_ORCHESTRATOR_REQUEST_UNSUPPORTED`, `METHODS_ORCHESTRATOR_DEVICE_UNAVAILABLE`, `METHODS_ORCHESTRATOR_METHOD_MEMBERS`, `METHODS_ORCHESTRATOR_METHOD_CODEC_MEMBERS`, `METHODS_ORCHESTRATOR_ACTION_CODEC_MEMBERS`, `METHODS_ORCHESTRATOR_REGISTRY_MEMBERS`, `METHODS_ORCHESTRATOR_UNSERVED_METHOD_MESSAGE`, `METHODS_ORCHESTRATOR_UNMET_BINDING_MESSAGE`, `METHODS_ORCHESTRATOR_PLACE_MISMATCH_MESSAGE`, `METHODS_ORCHESTRATOR_REPEAT_MESSAGE`, `METHODS_ORCHESTRATOR_ZERO_KEY_MESSAGE`, `METHODS_ORCHESTRATOR_FOREIGN_ACTION_MESSAGE`, `METHODS_ORCHESTRATOR_UNKNOWN_VALUE_MESSAGE`, `METHODS_ORCHESTRATOR_VERDICT_ANSWER_MESSAGE`, `METHODS_ORCHESTRATOR_BYTES_ANSWER_MESSAGE`, `METHODS_ORCHESTRATOR_INPUT_ANSWER_MESSAGE`, `METHODS_ORCHESTRATOR_ENROLL_ANSWER_MESSAGE`, `METHODS_ORCHESTRATOR_ENROLL_KINDS`, `METHODS_ORCHESTRATOR_NOT_STRING_MESSAGE`, `METHODS_ORCHESTRATOR_NOT_ITERABLE_MESSAGE`, `METHODS_ORCHESTRATOR_ENTRY_PAIR_MESSAGE`, `METHODS_ORCHESTRATOR_ENTRY_LENGTH`, `FORMATS_MISSING_MESSAGE` and `REPLY_FAILURE_KIND`, the kind every `ReplyFailure` carries.
