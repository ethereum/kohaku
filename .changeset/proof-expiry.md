A gathering now reports when a filed proof expires, and `complete` refuses an expired one. New: the optional codec member `IMethodCodec.proofExpiry(config, proof)`, the first block timestamp, in seconds, at which the module refuses the proof under the config for its age; it is absent where a method's proofs do not age, and is called only on bytes `decodeConfig` and `decodeProof` accept. The zkPassport codec provides it as the proof's date, the outer proof's public input `METHOD_ZKPASSPORT_PROOF_DATE_INPUT` (2), plus the config's `validityPeriodInSeconds`, as the module's root verifier measures it, and throws a `RangeError` with the new `METHOD_ZKPASSPORT_PROOF_DATE_MESSAGE` for a proof with fewer than `METHOD_ZKPASSPORT_SCOPED_MIN_PUBLIC_INPUTS` (8) public inputs; the wallet, passkey and Aadhaar codecs declare none. The recovery client's `assess` asks the codec of the implementation its method registry holds for each filed reply's method, and appends to the window's findings the new error `proof.expired` (subject `request`, values `place`, `expiresAt` and `moment`) for each proof whose expiry the caller's `now` has reached, then the new warning `proof.expiring` (subject `request`, values `place`, `expiresAt` and `validUntil`) for each that expires after `now` and at or before the request's `validUntil`, each in place order. A place whose method is not registered, whose codec declares no `proofExpiry`, or whose decode or call throws gets no finding, and a `proofExpiry` that is present but not a function throws a `TypeError`. After its existing refusals, `complete` throws a `KitRefusalError` with the new `GATHERING_PROOF_EXPIRED_MESSAGE` and exactly the chosen places' `proof.expired` findings where `now` has reached a chosen proof's expiry; the caller asks that approver again or passes a selection without the place. The codes are `proof.expired` in `REQUEST_ERROR_CODES`, after `proof.place-out-of-range`, and `proof.expiring` in `REQUEST_WARNING_CODES`, after `cancel.window-late`; only the gathering raises them. `validateRequest`, the prepares, the `Gathering`, `Reply` and `Assessment` shapes, `OrderRefusal` and the zkPassport stack's seven-day default validity are unchanged, and no record member is added.

Compatibility: the closed sets `REQUEST_ERROR_CODES` and `REQUEST_WARNING_CODES`, and with them the `ErrorCode` and `WarningCode` unions, grew by one member each, so a consumer that keeps an exhaustive map or switch over every code must add `proof.expired` and `proof.expiring` before it compiles again; a consumer that reads findings as data is unaffected. An assessment with no registered method whose codec states an expiry is unchanged. A completion that used to submit an expired zkPassport proof, which the module refuses, now throws before any prepare. The signing request still lets the zkPassport app answer with a proof up to seven days old, whatever validity period the committed config carries.
