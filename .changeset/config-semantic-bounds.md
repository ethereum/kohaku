`validateSetup` and the setup client's `validateSetup` now raise the error `credential.config-malformed` for a credential whose config decodes but holds a value that never verifies or that the SDK does not support, where before they judged its layout alone: an Aadhaar freshness window under `METHOD_AADHAAR_MIN_FRESHNESS_WINDOW` (one hour) or an Aadhaar nullifier or nullifier seed at or above `METHOD_AADHAAR_SNARK_SCALAR_FIELD`; the zero wallet signer; a zero zkPassport identifier or a validity period outside `METHOD_ZKPASSPORT_MIN_VALIDITY` (1 second) to `METHOD_ZKPASSPORT_MAX_VALIDITY` (2^53 − 1 seconds, the largest safe integer, since the stack reports the period as a number; this upper bound is the SDK's own limit, and a longer period may still verify on chain); and a passkey key that is not a point on P-256. No config a shipped enrollment writes raises it. Every such finding now carries `reason`, a value of the new constant `VALIDATION_CONFIG_FAULTS`: `'layout'` where the config does not decode, `'bound'` where it decodes to a refused value, and a bound finding also carries `fields`, the refused config fields in layout order. A place gets at most one finding, its layout judged first. New: the optional member `IMethodCodec.outOfBounds(config)`, which names those fields (none where every bound holds) and which the four shipped codecs implement; their `encodeConfig` and `decodeConfig` are unchanged, so the zero signer still encodes and decodes. `MethodReads.codec` widens to `Pick<IMethodCodec, 'decodeConfig' | 'outOfBounds'>`; `validateSetup` refuses with a `TypeError` an `outOfBounds` on any reads entry that is present and not a function, and reports a config whose `outOfBounds` throws or answers anything but an array of strings as a bound finding with `fields: []`. New constants: `VALIDATION_CONFIG_FAULTS`, `METHOD_ZKPASSPORT_MIN_VALIDITY` and `METHOD_ZKPASSPORT_MAX_VALIDITY`. `describeSetup` is unchanged.

Compatibility: no integrator call site needs a change, and `ErrorCode` and the setup error catalogue are unchanged, so a screen that already handles `credential.config-malformed` shows the new findings. Every `credential.config-malformed` finding now carries `reason`, so a consumer that deep-compares its values with `{ place, module, bytes }` sees one more member. An `IMethodCodec` implementation without `outOfBounds` is judged on its layout as before.
