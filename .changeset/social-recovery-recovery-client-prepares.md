Complete `RecoveryClient`, which now implements `IRecoveryClient`: `getApproverRequests`, `addApproverReply` and `assess` over the gathering record; `complete`, which refuses a passed window or an unsatisfied rule with a `KitRefusalError` carrying the findings and returns the request with the chosen proofs; `prepareStartAttempt` and `prepareCancelByProofs`, which check the request's shape and binding (and that an opening's payload decodes) and prepare and simulate the manager call at one pinned block without running request validation; `prepareCancelByOwner`; `prepareCancelByVeto` over the waiting attempt's id; `prepareExecuteHandover`, which checks the attempt against the manager's, refuses a spend a stopped method would veto, and composes the action's `executeHandover(account, payload)` with the batch it runs described; and `recoveryState`, the manager's state with the inferred removed key at one pinned block. The constructor takes a trailing `versionEscaped` flag that refuses every prepare. `prepareCommitSetup` no longer runs `validateSetup`: the integrator validates the draft first. `SETUP_CLIENT_VALIDATION_REFUSED_MESSAGE` is removed since `prepareCommitSetup` no longer validates the draft; an encrypted backup too wide to seal is refused before any read with `SETUP_CLIENT_BACKUP_TOO_WIDE_MESSAGE`. Add the `executeHandover`, `consume` and ERC-20 `transfer` ABI constants and the new `RECOVERY_CLIENT_` messages.
