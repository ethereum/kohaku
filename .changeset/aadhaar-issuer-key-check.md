Aadhaar enrollment and replies refuse a proof whose issuer key is not the method's trusted key. The Aadhaar `enrollInput` and `signingInput` take an optional `trustedKeys` parameter, named by the new constant `METHOD_AADHAAR_TRUSTED_KEYS_PARAM`. It holds the method module's `Parties.trustedKeys` exactly as the integrator read them with `trustedParties(module)`: an array of exactly one 32-byte hex word. Any other shape throws a `TypeError` naming `trustedKeys`, with the new `METHOD_AADHAAR_TRUSTED_KEYS_MESSAGE`, before any stack call. The word is copied onto the input as `trustedKey`, a bigint, so its case does not matter. After proving, `configFrom` compares the proof's issuer-key input (`pubkeyHash`, public input 0) with it after the nullifier and seed checks, and `replyFrom` does so after the binding and freshness checks and before the local verdict. A mismatch answers the new reply-failure cause `material-untrusted` through the new constant `METHOD_AADHAAR_MATERIAL_UNTRUSTED`: the material proves, but under an issuer key or version the method's module does not trust now, so the page can ask the guardian for a current QR. `REPLY_FAILURE_CAUSES`, and with it `ReplyFailureCause`, `ReplyFailure` and `EnrollFailure`, gains `material-untrusted` directly after `material-rejected`, six causes. A binding or freshness failure stays `material-rejected` and an abort `device-refused`. A proof under the trusted key that the installed stack cannot check locally still answers `not-judged` and is handed on, leaving the chain to judge it. A hand-built input whose `trustedKey` is not a `uint256` bigint is `material-rejected`. Without the parameter every input, config, reply and verdict is unchanged. The comparison runs after proving only, since the SDK does not compute the circuit's hash of the certificate's key.

Compatibility: an exhaustive switch on `ReplyFailureCause` gains a case, `material-untrusted`. Pass `trustedKeys` from a `trustedParties(module)` read of the Aadhaar method's module made when the step opens, since a word read before the module rotates its key refuses current proofs. Integrations that pass nothing see no change.
