The holder chooses the Aadhaar freshness window, 75 minutes by default, and the setup description shows it. The Aadhaar `enrollInput` takes an optional `freshnessWindow` parameter, named by the new constant `METHOD_AADHAAR_WINDOW_PARAM`. It is a bigint or a safe integer of seconds, at least `METHOD_AADHAAR_MIN_FRESHNESS_WINDOW` (3600) and below 2^256, with no other ceiling. Another type throws a `TypeError` with the new `METHOD_AADHAAR_WINDOW_TYPE_MESSAGE`, and a value out of range a `RangeError` with the new `METHOD_AADHAAR_WINDOW_RANGE_MESSAGE`; both name `freshnessWindow`. The ceremony input now carries `freshnessWindow` as a bigint, `METHOD_AADHAAR_FRESHNESS_WINDOW` where the parameters name none. `configFrom` writes that window as the config's third word. An input without one, such as one made before this change, gets the default. An input whose window is not a bigint of at least 3600 that fits a `uint256` is `material-rejected` before proving. `signingInput` ignores the parameter, since the config holds the window. `describeSetup` returns the new required member `SetupDescription.aadhaarWindows`: for each credential of the deployment's Aadhaar method, in place order, its `place` and the `freshnessWindow` its config holds, in seconds. A window under the minimum is shown as held, and validation still reports it. A config that is not the 96-byte layout of nullifier, seed and window throws a `TypeError` naming `draft.clauses[c].credentials[i].config`. Changed: `METHOD_AADHAAR_FRESHNESS_WINDOW` is now `4500n` (75 minutes) instead of `86400n`. New: `METHOD_AADHAAR_WINDOW_PARAM`, `METHOD_AADHAAR_WINDOW_TYPE_MESSAGE` and `METHOD_AADHAAR_WINDOW_RANGE_MESSAGE`, exported from both entries. The config layout, the codec, the bounds, `replyFrom`, `verify` and the proving arguments are unchanged.

Compatibility: new Aadhaar enrollments write a 75-minute window instead of 24 hours unless the holder passes `freshnessWindow`. An approval must then reach the chain within 75 minutes of the QR's signing time, which the QR records to the hour, so a freshly downloaded QR stays usable for at least 15 minutes. A page should show the holder the window and the tradeoff before committing: a longer window is easier for the guardian and widens the exposure of a copied QR by the same amount. Configs already committed keep their window, since the commitment fixes it. Code that read `METHOD_AADHAAR_FRESHNESS_WINDOW` as every config's window must read the window from the config. Code that builds `SetupDescription` records of its own must add `aadhaarWindows`.
