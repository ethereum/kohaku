`validateRequest` now names a request made under another setup nonce than the manager holds, and an opening while no setup stands, with errors of their own instead of `request.body-mismatch`. New: the error codes `request.no-setup` (subject `request`, values `account` and `action`, checksummed), raised on an opening alone where the manager's `setupCommitment` is the zero commitment `CLIENT_CORE_NO_SETUP_COMMITMENT`, in any case, as the manager reverts with `PolicyManager_NoSetup`; and `request.setup-nonce` (subject `request`, values `setupNonce`, the request's, and `expected`, the manager's), raised on either kind where the two differ, as the manager reverts with `PolicyManager_WrongSetupNonce`; both in `REQUEST_ERROR_CODES` after `request.stale-attempt`, `request.no-setup` first. The state findings come in the manager's order, no existing row moved relative to another: on an opening `request.no-setup`, `request.attempt-active`, `request.setup-nonce`, `request.attempt-id`; on a cancellation `request.no-active-attempt`, `request.setup-nonce`, `request.attempt-id`, `request.stale-attempt`. `request.body-mismatch` is now recomputed under the manager's setup nonce, as the manager recomputes it, and is not raised while no setup stands: the current body under a moved nonce gets `request.setup-nonce` alone, a changed body under a moved nonce gets both, and a changed body under the current nonce gets `request.body-mismatch` with the same values as before. A cancellation after the setup was cleared gets `request.no-active-attempt` and `request.setup-nonce`, never `request.no-setup`. The prepares, the gatherings and the recovery client are unchanged.

Compatibility: the closed set `REQUEST_ERROR_CODES`, and with it the `ErrorCode` union, grew by two members, so a consumer that keeps an exhaustive map or switch over every error code must add `request.no-setup` and `request.setup-nonce` before it compiles again; a consumer that reads findings as data is unaffected. A request retired by a setup update, which used to get `request.body-mismatch`, now gets `request.setup-nonce`, the cue to gather new approvals; a `request.body-mismatch` raised beside it carries the commitment recomputed under the manager's nonce, not the request's.
