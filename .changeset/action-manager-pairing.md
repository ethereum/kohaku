Every client build (`buildSetupClient`, `buildRecoveryClient`, `recoveryAction()` and `build`) now reads the bound action's `MANAGER()` once, from the zero address at the read tag, as its last construction read, after `version()` or after a handed manager reading; the action is the `withRecoveryAction` address, else the descriptor's. An answer naming another manager than the descriptor's refuses with a `KitRefusalError` carrying the new constant `BUILDER_ACTION_MANAGER_MESSAGE`, whatever `withVersionEscape()`, and caches nothing; a revert or an answer that does not decode as one address builds as before, and any other provider rejection propagates. The orchestrator build reads nothing, as before. `validateSetup`, pure and on the setup client, reports such an action as the error `action.manager-mismatch` (subject `action`, values `action`, `manager`, the descriptor's, and `actionManager`, the action's answer, all checksummed), beside any `account.not-deployed`, `action.unsupported` or `action.unaudited`, since the action spends only its own manager's attempts and a setup committed to another one can never execute. The setup client's `validateSetup` and `describeSetup` each make one more `eth_call`, `MANAGER()` at the pinned block, in the same round trip as the action's other reads; `describeSetup` output is unchanged. New: the constant `RECOVERY_ACTION_MANAGER_ABI`, the error code `action.manager-mismatch` in `SETUP_ERROR_CODES`, after `account.not-deployed`, and the member `ActionReads.manager`, a `ReadResult<Address>`.

Breaking: `ActionReads` gains the required member `manager`, so a caller of the pure `validateSetup` or `describeSetup` with its own reads must supply it (`{ answered: false }` where it read nothing); both throw a `TypeError` where it is missing or malformed.

Compatibility: a build over a descriptor or `withRecoveryAction` address whose action answers `MANAGER()` with another manager, which used to succeed, now refuses; such a setup can never execute, so commit again under a matching pair. The closed set `SETUP_ERROR_CODES`, and with it the `ErrorCode` union, grew by one member, so a consumer that keeps an exhaustive map or switch over every error code must add `action.manager-mismatch` before it compiles again; a consumer that reads findings as data is unaffected.
